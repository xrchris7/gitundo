What you get

A safety net that lives where git already lives — ordinary commits on a hidden ref, protected by git's own integrity model.

Snapshot anything

Staged and unstaged and untracked files, deletions, symlinks, binaries. Ignored files & the stash are never captured.

Undo the un-undoable

Recover work destroyed by reset --hard, clean -fdx, checkout -f — even files that were never committed.

Auto-guard

Snapshots automatically before destructive commands (reset --hard, clean -dfx…). Installed with one command.

Browse & tag history

list, diff, and tag demo-ready — every intermediate state is findable and restorable by number, tag or id.

Zero-invasion

Only a hidden ref is ever written. The index, working tree and history stay exactly as you left them. Restore never rewrites history.

Editor integration

Official VS Code extension: sidebar checkpoints, one-click snapshot, restore & diff, and a live status bar.

How it works

Checkpoints are real git commits hanging off refs/gitundo/checkpoints — so deduplication, integrity and shareability are all handled by git itself.

Snap

gitundo snap "before the refactor" stores the complete working state as a lightweight checkpoint.

Break things

Experiment freely — or let the auto-guard snapshot for you before reset --hard, clean and friends.

Restore

gitundo restore (by number, tag or id) puts everything back. Local edits are kept aside as *.gitundo-keep, never clobbered.

Commands

Selectors everywhere: latest, a number (snapshots ago), a tag name, or an object-id prefix.

CommandWhat it does
gitundo snap [msg] [-t TAG]Snapshot the current working state
gitundo listBrowse checkpoints, newest first
gitundo restore [SEL]Restore the working tree to a checkpoint
gitundo diff [SEL]See exactly what a snapshot saved
gitundo tag NAME [SEL]Name a checkpoint — tagged ones survive pruning
gitundo prune -k 50Keep the newest 50 + tagged; reclaim the rest
gitundo autowrapInstall the shell auto-guard (bash / zsh)
gitundo statusGuard state, recent checkpoints, storage used
